The numpy ideas you need

1. An ndarray is a block of numbers plus a shape

A Python list holds pointers to objects that can be anything. A numpy array holds raw numbers of one type, side by side in memory. That is why it is fast, and why it has a shape and a dtype.

import numpy as np
a = np.array([[1, 2, 3], [4, 5, 6]])
a.shape   # (2, 3)   two rows, three columns
a.dtype   # dtype('int64')
a.ndim    # 2        the number of axes

2. Axis order for an image is (rows, columns, channels)

This is the single most common confusion of the day. Pillow reports an image size as (width, height). Numpy reports the same image as (height, width, channels). They are swapped.

FilePillow .sizeNumpy .shape
landscape.jpg(450, 257)(257, 450, 3)
animal.jpeg(1024, 768)(768, 1024, 3)

The 3 is the channel axis: red, green, blue. So image[10, 20] is the pixel on row 10, column 20, and it is an array of three numbers. image[10, 20, 0] is the red value of that pixel, a number from 0 to 255.

3. Slicing keeps the axis, indexing drops it

This one decides whether ex03 prints (400, 400, 1) or (400, 400).

image[:, :, 0]      # index  -> shape (h, w)      the axis is gone
image[:, :, 0:1]    # slice  -> shape (h, w, 1)   the axis stays, size 1

Both hold the same numbers. Only the shape differs. The subject prints (400, 400, 1) or (400, 400), which means either answer is accepted, but you must know which one your code produced and why.

4. A slice is a view, not a copy

A slice shares memory with the original array. If you write into the slice, you write into the original.

view = image[0:10]
view[0, 0, 0] = 255     # image is changed too

copy = image[0:10].copy()
copy[0, 0, 0] = 255     # image is untouched

This is why every filter in ex05 starts with array.copy(). Without it, ft_red would destroy the array before ft_green ever sees it, and the four images after the first would all be wrong.

5. Broadcasting

An operation between two arrays of different shapes stretches the smaller one, without allocating the stretched copy. Numpy lines the shapes up from the right and accepts an axis when the sizes are equal or one of them is 1.

image        (400, 400, 3)
column       (400, 400, 1)
result       (400, 400, 3)     the size-1 axis is repeated 3 times

That rule alone solves ft_grey under a restriction that forbids + and *. Broadcasting is not an operator, so it stays legal.

6. dtype is uint8, and it wraps around

Image pixels are uint8: whole numbers from 0 to 255. Above 255 the value wraps to 0, it does not clip.

np.uint8(250) + np.uint8(10)     # 4, not 260 and not 255

255 - array is safe because the result of every subtraction stays in 0..255. An invert written as array * -1 + 255 would not be.

ex00 - Give my BMI

Files: give_bmi.py, tester.py

The ask

Two lists in, one list of BMI values out. Then a second function turning that list into booleans against a limit. Handle the error cases.

The code

def _check_list(values: list, name: str) -> None:
    """Raise if values is not a list of int or float."""
    if not isinstance(values, list):
        raise TypeError(f"{name} must be a list")
    for item in values:
        if isinstance(item, bool) or not isinstance(item, (int, float)):
            raise TypeError(f"{name} must hold only int or float")


def give_bmi(height: list[int | float],
             weight: list[int | float]) -> list[int | float]:
    """Return the BMI of each person as a list of floats."""
    _check_list(height, "height")
    _check_list(weight, "weight")
    if len(height) != len(weight):
        raise ValueError("height and weight must have the same size")
    if len(height) == 0:
        raise ValueError("height and weight must not be empty")
    for value in height:
        if value <= 0:
            raise ValueError("height must be greater than 0")
    return [w / (h * h) for h, w in zip(height, weight)]


def apply_limit(bmi: list[int | float], limit: int) -> list[bool]:
    """Return True for each BMI value above the limit."""
    _check_list(bmi, "bmi")
    if isinstance(limit, bool) or not isinstance(limit, int):
        raise TypeError("limit must be an int")
    return [value > limit for value in bmi]

Line by line

  • _check_list is one validator used by both public functions. The leading underscore is the Python convention for "internal, do not import this".
  • BMI is weight in kilograms divided by height in metres squared. The formula is w / (h * h).
  • zip(height, weight) walks the two lists together. The length check above it is what makes the zip safe, because zip silently stops at the shorter list instead of complaining.
  • apply_limit returns value > limit, strictly above. The subject's own example proves it: a BMI of 22.5 against a limit of 26 gives False.

Output

$ python tester.py
[22.507863455018317, 29.0359168241966] <class 'list'>
[False, True]

Trap 1 - bool is an int. In Python bool inherits from int, so isinstance(True, int) is True and a naive check lets give_bmi([True], [70]) through, computing a BMI for a person 1 metre tall. The explicit isinstance(item, bool) test rejects it first.

Trap 2 - a height of zero. Plain Python raises ZeroDivisionError; numpy would instead return inf and print a warning. Either way the caller gets nonsense, so heights of 0 or less are refused up front.

Trap 3 - the return type. The expected output ends with <class 'list'>. If you compute with numpy you must call .tolist(), otherwise you return an ndarray and fail that one printed line.

ex01 - 2D array

Files: array2D.py, tester.py

The ask

Take a 2D list, print its shape, return a truncated version made with slicing.

The code

import numpy as np


def slice_me(family: list, start: int, end: int) -> list:
    """Print the shape of a 2D list, then return a sliced copy of it."""
    if not isinstance(family, list) or len(family) == 0:
        raise TypeError("family must be a non-empty list")
    for row in family:
        if not isinstance(row, list):
            raise TypeError("family must be a list of lists")
        if len(row) != len(family[0]):
            raise ValueError("every row must have the same size")
    if isinstance(start, bool) or not isinstance(start, int):
        raise TypeError("start must be an int")
    if isinstance(end, bool) or not isinstance(end, int):
        raise TypeError("end must be an int")
    array = np.array(family)
    print(f"My shape is : {array.shape}")
    sliced = array[start:end]
    print(f"My new shape is : {sliced.shape}")
    return sliced.tolist()

Line by line

  • The validation runs before np.array, because numpy accepts ragged input by quietly building an array of Python objects instead of numbers, and then the shape is (4,) rather than (4, 2). Checking first gives a clear message instead of a confusing shape.
  • array[start:end] slices along axis 0 only, so it selects rows and keeps every column. That is exactly what the subject asks for.
  • Negative values work for free: slice_me(family, 1, -2) means "from row 1 up to two rows before the end", which is one row.

Output

$ python tester.py
My shape is : (4, 2)
My new shape is : (2, 2)
[[1.8, 78.4], [2.15, 102.7]]
My shape is : (4, 2)
My new shape is : (1, 2)
[[2.15, 102.7]]

Trap - "You must use the slicing method". A loop that appends rows is banned even if the output is identical. The single expression array[start:end] is the point of the exercise.

Trap - the space before the colon. The expected output is My shape is : (4, 2), with a space on both sides of the colon. A peer diffing your output line by line will see it.

ex02 - Load my image

Files: load_image.py, tester.py

The ask

Load an image, print its format, return its pixels in RGB. Handle JPG and JPEG. Handle any error with a clear message.

The code

import numpy as np
from PIL import Image, UnidentifiedImageError


def ft_load(path: str) -> np.ndarray:
    """Load a JPG image, print its shape, and return its RGB pixels."""
    if not isinstance(path, str):
        raise TypeError("path must be a str")
    if not path.lower().endswith((".jpg", ".jpeg")):
        raise ValueError(f"{path}: only JPG and JPEG files are supported")
    try:
        with Image.open(path) as image:
            pixels = np.array(image.convert("RGB"))
    except FileNotFoundError:
        raise FileNotFoundError(f"{path}: no such file")
    except UnidentifiedImageError:
        raise ValueError(f"{path}: the file is not a readable image")
    except OSError as error:
        raise OSError(f"{path}: {error}")
    print(f"The shape of image is: {pixels.shape}")
    return pixels

Line by line

  • path.lower().endswith((".jpg", ".jpeg")) - endswith accepts a tuple, so this is one test for both extensions, and .lower() makes PHOTO.JPG pass.
  • with Image.open(path) - Pillow is lazy. open only reads the header; the pixels are decoded when they are first needed. The with block closes the file handle either way.
  • .convert("RGB") - this is what guarantees three channels. A greyscale JPEG opens in mode L and would otherwise give a shape of (h, w), breaking every later exercise. Convert also drops the alpha channel of formats that carry one.
  • np.array(image) - Pillow image to numpy array. One call, no loop over pixels.
  • The three except clauses turn a library traceback into one clear sentence that names the file.

Output

$ python tester.py
The shape of image is: (257, 450, 3)
[[[19 42 83]
  [23 42 84]
  [28 43 84]
  ...
  [ 0  0  0]
  [ 1  1  1]
  [ 1  1  1]]]

Numpy prints the ... itself. Above 1000 elements it summarises, showing the first three and the last three of each axis. Nothing in the code does that.

Trap - the errors must be caught somewhere. The general rules say an uncaught exception invalidates the exercise. This design raises inside ft_load, where the problem is known, and catches in main, where the program can still print something useful and exit cleanly. Every tester.py here has that guard.

Trap - the extension is not the format. A text file renamed to .jpg passes the extension test and then fails inside Pillow. That is the UnidentifiedImageError branch. Try it during your defense, it is a good answer to give before the evaluator asks.

ex03 - Zoom on me

Files: load_image.py, zoom.py

The ask

Load animal.jpeg, print the size on both axes, the number of channels and the pixel content, then display the zoomed image with the scale on the x and y axis.

The code

import matplotlib.pyplot as plt
from load_image import ft_load


def main():
    """Load animal.jpeg, zoom on a 400x400 square, and display it."""
    try:
        pixels = ft_load("animal.jpeg")
        print(pixels)
        zoom = pixels[100:500, 450:850, 0:1]
        print(f"New shape after slicing: {zoom.shape}")
        print(zoom)
        plt.imshow(zoom[:, :, 0], cmap="gray")
        plt.show()
    except Exception as error:
        print(f"{type(error).__name__}: {error}")


if __name__ == "__main__":
    main()

Line by line

  • pixels[100:500, 450:850, 0:1] is three slices in one expression: rows 100 to 499, columns 450 to 849, channel 0 only. 400 rows, 400 columns, 1 channel. The window lands on the raccoon's eyes and nose.
  • The zoom is not a resize. Nothing is interpolated or stretched; a rectangle of the original pixels is selected and matplotlib draws it larger on screen.
  • 0:1 rather than 0 keeps the third axis, which is what prints (400, 400, 1).
  • plt.imshow refuses a shape of (400, 400, 1): it wants either (h, w) for a single channel or (h, w, 3) for colour. So the display line passes zoom[:, :, 0], shape (400, 400).
  • cmap="gray" - a single-channel array carries no colour. Without a colour map matplotlib paints it with its default blue-green scale.
  • The scale on both axes is the matplotlib default, so the subject's requirement costs nothing extra. Do not call plt.axis("off").

ex04 - Rotate me

Files: load_image.py, rotate.py

The ask

Cut a square part of animal.jpeg and transpose it. Display it, print the new shape and the data. No library is allowed for the transpose.

The code

def ft_transpose(array: np.ndarray) -> np.ndarray:
    """Return the transpose of a 2D array, written without a library."""
    if array.ndim != 2:
        raise ValueError("the array to transpose must be 2D")
    height, width = array.shape
    return np.array([[array[y][x] for y in range(height)]
                     for x in range(width)], dtype=array.dtype)


def main():
    """Load animal.jpeg, cut a square, transpose it, and display it."""
    try:
        pixels = ft_load("animal.jpeg")
        square = pixels[100:500, 450:850, 0]
        print(f"The shape of image is: {square.shape}")
        print(square)
        rotated = ft_transpose(square)
        print(f"New shape after Transpose: {rotated.shape}")
        print(rotated)
        plt.imshow(rotated, cmap="gray")
        plt.show()
    except Exception as error:
        print(f"{type(error).__name__}: {error}")

What a transpose is

The transpose swaps rows and columns. The value at row y, column x moves to row x, column y. On an image it is a mirror across the main diagonal: the result looks rotated a quarter turn and flipped.

[[1, 2, 3],        [[1, 4],
 [4, 5, 6]]   ->    [2, 5],
                    [3, 6]]

shape (2, 3)       shape (3, 2)

Read the comprehension out loud in that order: the outer loop for x in range(width) builds the rows of the result, and the inner for y in range(height) fills each of them by walking down one column of the input. Line x of the output is column x of the input.

Output

$ python rotate.py
The shape of image is: (400, 400)
[[167 161 163 ... 105 114 115]
 ...
New shape after Transpose: (400, 400)
[[167 161 163 ... 105 114 115]
 [180 171 170 ... 112 114 116]
 [194 184 178 ... 122 126 119]
 ...

The check that it worked: 167 180 194 was the start of the first row before, and it is the start of the first column after.

Trap - what "no library" bans. array.T, np.transpose, np.swapaxes, np.rot90 and zip(*rows) are all off the table. The index swap must be written by hand. np.array(...) around the result is fine: it packs a list of lists, it does no transposing.

Trap - the square must be 2D. A (400, 400, 1) array has three axes and there is no single answer for its transpose, so the crop here indexes with 0, not 0:1, giving (400, 400). The ndim guard in ft_transpose states that requirement instead of failing on a strange index error.

Trap - it must stay square. Transposing a non-square crop still works, but it returns a different shape, and the print no longer matches the subject.

ex05 - Pimp my image

Files: load_image.py, pimp_image.py, tester.py

The ask

Five colour filters. The image shape must not change. And each function may use only the operators it is given:

FunctionAllowed operatorsThe idea
ft_invert= + - *255 minus every value
ft_red= * multiply green and blue by 0
ft_green= - subtract red and blue from themselves
ft_blue= assign 0 to red and green
ft_grey= / broadcast one channel over all three

The code

def ft_invert(array: np.ndarray) -> np.ndarray:
    """Inverts the color of the image received."""
    inverted = 255 - array
    _show(inverted, "Invert")
    return inverted


def ft_red(array: np.ndarray) -> np.ndarray:
    """Keeps only the red channel of the image received."""
    red = array.copy()
    red[:, :, 1] = red[:, :, 1] * 0
    red[:, :, 2] = red[:, :, 2] * 0
    _show(red, "Red")
    return red


def ft_green(array: np.ndarray) -> np.ndarray:
    """Keeps only the green channel of the image received."""
    green = array.copy()
    green[:, :, 0] = green[:, :, 0] - green[:, :, 0]
    green[:, :, 2] = green[:, :, 2] - green[:, :, 2]
    _show(green, "Green")
    return green


def ft_blue(array: np.ndarray) -> np.ndarray:
    """Keeps only the blue channel of the image received."""
    blue = array.copy()
    blue[:, :, 0] = 0
    blue[:, :, 1] = 0
    _show(blue, "Blue")
    return blue


def ft_grey(array: np.ndarray) -> np.ndarray:
    """Turns the image received into shades of grey."""
    grey = array.copy()
    grey[:, :, :] = grey[:, :, 0:1] / 1
    _show(grey, "Grey")
    return grey

_show is the shared three-line helper that draws the result, so the five filters stay readable:

def _show(array: np.ndarray, title: str) -> None:
    """Display an array as an image in a matplotlib window."""
    plt.imshow(array)
    plt.title(title)
    plt.show()

Why each one is legal

  • invert - 255 - array uses = and -. A dark pixel becomes bright, and the colour flips to its opposite. The scalar 255 is broadcast over the whole array.
  • red - with only = and * you cannot write a zero directly on the right of an assignment to a slice and still use an operator, so multiply the channel by 0. Red is untouched, green and blue are wiped.
  • green - with only = and -, any value minus itself is zero. green[:, :, 0] - green[:, :, 0] is a whole channel of zeros without ever writing the number 0.
  • blue - the easiest one. Plain assignment of a scalar into a slice, which numpy broadcasts across every pixel of that channel.
  • grey - the interesting one. grey[:, :, 0:1] has shape (h, w, 1). Assigning it into grey[:, :, :], shape (h, w, 3), makes numpy broadcast the size-1 axis three times, so the three channels end up equal. Equal R, G and B is exactly the definition of a grey pixel. / 1 is there because the rules allow / and it costs nothing; the real work is done by the broadcast.

Output

$ python tester.py
The shape of image is: (257, 450, 3)
[[[19 42 83]
  ...
Inverts the color of the image received.

Plus five windows, one per filter. The last line is ft_invert.__doc__, which is why every function carries a docstring.

Trap - the copy. Without array.copy() the first filter overwrites the caller's array and the next four operate on damaged data. The tester calls all five on the same array, so the bug is visible immediately: the green image would come out black.

Trap - the shape must stay the same. A grey image is (h, w, 3) with three equal channels, not (h, w). This is stated in the subject and it is the reason the broadcast trick is the right answer.

Trap - the operator list is a whitelist. np.dot, np.mean, cv2.cvtColor or a weighted luminance formula are all out for grey, because the formula needs + and *. The grey here is built from the red channel, which is the honest consequence of the restriction. Be ready to say that.

Defense: the questions and the answers

Why is bool rejected in ex00?

bool is a subclass of int, so isinstance(True, int) is True. Without the explicit test, True would be accepted as a height of 1 metre.

Why (257, 450, 3) and not (450, 257, 3)?

Numpy orders axes as rows, columns, channels. Pillow reports size as width, height. The image is 450 wide and 257 tall.

Difference between [:, :, 0] and [:, :, 0:1]?

Same numbers. Indexing drops the axis and gives (h, w); slicing keeps it and gives (h, w, 1).

Did you use a library for the transpose?

No. ft_transpose is a list comprehension that swaps the two indexes by hand. np.array only packs the finished list of lists.

Why .copy() in every filter?

A numpy slice is a view on the same memory. Writing into it changes the original array, and the tester reuses that array for all five filters.

How is grey legal with only = and / ?

Broadcasting is not an operator. Assigning a (h, w, 1) slice into a (h, w, 3) slice repeats it across the three channels, so R, G and B become equal.

Where does the ... in the printed array come from?

From numpy. Above 1000 elements it summarises an array instead of printing every value.

What happens on a .png, or a missing file?

A clear message: only JPG and JPEG files are supported, or no such file. No traceback, because main catches.

Is the zoom a resize?

No. It selects a rectangle of existing pixels. Nothing is interpolated; matplotlib just draws those 400x400 pixels larger.

The checklist before you call a peer

  • flake8 ex0*/ prints nothing.
  • Every function has a docstring, including main.
  • No code in the global scope. Every program ends with if __name__ == "__main__": main().
  • No wildcard import. No global variable.
  • Every program survives a missing file, a wrong type and a wrong size without a traceback.
  • Each exercise directory holds the images it opens, and runs from inside itself.
